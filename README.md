# misevent — Ελληνική μισθοδοσία, event-sourced (Python)

Εφαρμογή ελληνικής μισθοδοσίας βασισμένη σε **Event Sourcing + CQRS** και σε
**ημερολόγιο υποχρεώσεων** (obligation calendar): η πρόσληψη γεννά ολόκληρο τον
κύκλο (παρουσίες → μισθοδοσία → πληρωμές → ΑΠΔ → ΦΜΥ → Δώρα), και κάθε
υποχρέωση κλείνει μόνη της όταν συμβεί το αντίστοιχο πραγματικό event.

Ο **πυρήνας είναι stdlib-only** (SQLite). Το **web UI** τρέχει σε Flask + htmx.

## Εκτέλεση

```bash
rm -f payroll.db && uv run demo.py     # πλήρες σενάριο end-to-end
uv run -m webapp                       # UI -> http://localhost:8000

uv run test_apd_files.py               # γραμμογράφηση ΑΠΔ ανά byte
uv run test_webapp.py                  # smoke test UI (ξαναφτιάχνει το payroll.db)
```

### Πρώτη σύνδεση

Σε κενό σύστημα (χωρίς κανέναν χρήστη) δημιουργείται αυτόματα ο διαχειριστής:

- **Email:** `admin@admin.app`
- **Κωδικός:** `changeme`

Ο κωδικός είναι προσωρινός: η πρώτη σύνδεση επιβάλλει αλλαγή.
Ορίζεται στο `misevent/app/auth.py` (`BOOTSTRAP_EMAIL` / `BOOTSTRAP_PASSWORD`).

## Αρχιτεκτονική

```
Commands (PayrollService) ──> EventStore (append-only SQLite, ΠΗΓΗ ΑΛΗΘΕΙΑΣ)
                                   │ pub/sub
              ┌────────────────────┴────────────────────┐
              ▼                                         ▼
        Projections                          ObligationScheduler
        (in-memory)                          (process manager:
                                              γεννά/κλείνει υποχρεώσεις)
```

Ο πίνακας `events` είναι η **μοναδική πηγή αλήθειας**. Τα υπόλοιπα είναι
παράγωγα και ξαναχτίζονται πλήρως με replay (`proj.rebuild(store)`). Κανένα
αποθηκευμένο event δεν τροποποιείται ποτέ — οι διορθώσεις γίνονται με νέα
«αντισταθμιστικά» events. Κατά τη δοκιμαστική ανάπτυξη το schema των events
παραμένει ενιαίο και η τοπική βάση αναδημιουργείται όταν αλλάζει.

| Αρχείο | Ρόλος |
|---|---|
| `events.py` | Τα domain events (frozen dataclasses) |
| `event_store.py` | Append-only store και pub/sub |
| `projections.py` | Κατάσταση από replay: `PersonState`, `EmploymentState`, `Obligation` |
| **`obligation_types.py`** | **Δηλωτικό μητρώο τύπων υποχρεώσεων** (αλυσίδα, προθεσμίες) |
| `scheduler.py` | Process manager: γεννά/κλείνει υποχρεώσεις βάσει του μητρώου |
| `dependencies.py` | Ανάγνωση του γράφου εξαρτήσεων (μπλοκαρισμένες/ελεύθερες) |
| `constraints.py` | Κανόνες εγκυρότητας (μοναδικότητα, σύμβαση, πρόγραμμα, επαναπρόσληψη) |
| `services.py` | `PayrollService` — τα commands, εδώ ζει το validation |
| `payroll_engine.py` | Καθαρές συναρτήσεις υπολογισμού (ΕΦΚΑ, ΦΜΥ, Δώρα, Επίδομα) |
| `config.py` | Συντελεστές **με ημερομηνίες ισχύος** (ΕΦΚΑ, ΤΕΚΑ, φόροι, κατώτατος) |
| `calendar_gr.py` | Ορθόδοξο Πάσχα, αργίες, τελευταία εργάσιμη μήνα |
| `apd_files.py` | Παραγωγή αρχείων ΑΠΔ (CSL01) e-ΕΦΚΑ & ΤΕΚΑ |
| `ergani.py` | Client REST API ΕΡΓΑΝΗ ΙΙ |
| `webapp/` | Flask + Jinja2 + htmx (μία σελίδα ανά οντότητα) |

## Person vs Employment

**Person** = το φυσικό πρόσωπο (σταθερή ταυτότητα: ΑΦΜ/ΑΜΚΑ/ΑΜΑ, ονόματα,
τέκνα). **Employment** = μια περίοδος απασχόλησης (σύμβαση, ασφαλιστικό
προφίλ, πρόγραμμα, άδειες, μισθοδοσία).

```
Person (μοναδικό ΑΦΜ / ΑΜΚΑ / Επώνυμο+Όνομα+Πατρώνυμο+ημ. γέννησης)
  ├── Employment  2024-01 → 2025-06   ← έληξε
  └── Employment  2026-03 → …         ← ΕΠΑΝΑΠΡΟΣΛΗΨΗ (ίδιο Person)
```

Η **επαναπρόσληψη** είναι νέο `start_employment()` στο ίδιο `person_id` — ποτέ
νέο Person. Απαγορεύεται όσο υπάρχει **ενεργή** απασχόληση (πρώτα αποχώρηση) και
πρέπει να είναι μετά τη λήξη της προηγούμενης περιόδου.

Στο UI, η πρόσληψη ξεκινά **πάντα με αναζήτηση** στο μητρώο (ΑΦΜ/ΑΜΚΑ/ΑΜΑ ή
όνομα): αν το πρόσωπο υπάρχει και είναι ανενεργό → επαναπρόσληψη χωρίς
επανακαταχώρηση στοιχείων· αλλιώς → φόρμα νέου προσώπου + απασχόλησης.

## Η αλυσίδα των υποχρεώσεων

Οι υποχρεώσεις είναι **επιπέδου εταιρείας** (μία ανά περίοδο για όλους μαζί) και
συνδέονται σε αλυσίδα: καμία δεν ενεργοποιείται πριν ολοκληρωθούν τα
προαπαιτούμενά της. Στο χρονολόγιο **δεν εμφανίζονται καν** όσες περιμένουν
προαπαιτούμενο — ξεκλειδώνουν μόλις αυτό τρέξει.

```
ΜΙΣΘΟΔΟΣΙΑ(προηγ. μήνα) ─> ΕΓΚΡΙΣΗ ΠΑΡΟΥΣΙΩΝ(μήνας) ─> ΜΙΣΘΟΔΟΣΙΑ(μήνας)
                                                             │
        ┌────────────────────────────────────────────────────┤
        ├─> ΠΛΗΡΩΜΗ ΜΙΣΘΩΝ
        ├─> ΑΠΔ e-ΕΦΚΑ ────────> ΚΑΤΑΒΟΛΗ ΕΦΚΑ
        ├─> ΑΠΔ ΤΕΚΑ ──────────> ΚΑΤΑΒΟΛΗ ΤΕΚΑ      (μόνο αν υπάρχει ΤΕΚΑ)
        ├─> ΔΗΛΩΣΗ ΦΜΥ ────────> ΚΑΤΑΒΟΛΗ ΦΜΥ
        │
        ├─ ΜΙΣΘΟΔΟΣΙΑ ΜΑΡΤΙΟΥ ──> ΔΩΡΟ ΠΑΣΧΑ ──────> ΚΑΤΑΒΟΛΗ ΔΩΡΟΥ
        └─ ΜΙΣΘΟΔΟΣΙΑ ΝΟΕΜΒΡΙΟΥ > ΔΩΡΟ ΧΡΙΣΤΟΥΓΕΝΝΩΝ > ΚΑΤΑΒΟΛΗ ΔΩΡΟΥ

1η ΚΑΝΟΝΙΚΗ ΑΔΕΙΑ ──> ΕΠΙΔΟΜΑ ΑΔΕΙΑΣ (στην περίοδο της άδειας) ──> ΚΑΤΑΒΟΛΗ
```

- **Κυλιόμενη**: η μισθοδοσία ενός μήνα «ανοίγει» αυτόματα τον επόμενο (και τα
  Δώρα της νέας χρονιάς όταν αλλάζει έτος).
- **Επίδομα Αδείας**: αντιδραστικό — γεννιέται στον μήνα της **πρώτης κανονικής
  άδειας κάθε εργαζόμενου**, ενιαία για όσους την πήραν εκείνον τον μήνα (άρα
  έως 12 περίοδοι/έτος).
- **Εκπρόθεσμες**: υποβάλλονται κανονικά — με κόκκινο κουμπί, ρητή προειδοποίηση
  και καταγραφή της καθυστέρησης στο μήνυμα.

### Παραμετροποίηση (obligation_types.py)

Η αλυσίδα **δεν είναι hardcoded**: κάθε τύπος υποχρέωσης είναι μία δηλωτική
εγγραφή — πότε γεννιέται (`spawn`), τι προθεσμία έχει (`due`), τι προαπαιτεί
(`requires`), ποια εντολή εκτελεί (`command`), αν επιδέχεται παράταση:

```python
_t("MONTHLY_PAYROLL", "Υπολογισμός μισθοδοσίας", "🧮",
   spawn="period", due=("eom", 0), command="run_monthly_payroll",
   requires=(("ATTENDANCE_APPROVAL", "same"),)),

_t("EASTER_GIFT", "Δώρο Πάσχα", "🥚",
   spawn="annual", due=("easter_minus", 4), command="run_easter_gifts",
   requires=(("MONTHLY_PAYROLL", "month:3"),), strict=True),
```

Το μητρώο κάνει `validate()` στο import (άγνωστοι τύποι, **κύκλοι**). Νέος τύπος
= μία εγγραφή εδώ + μία εντολή στο `webapp/actions.py::COMMANDS`.

⚠️ Οι **προθεσμίες δεν είναι αναδρομικές**: ήδη προγραμματισμένες υποχρεώσεις
κρατούν την προθεσμία που γράφτηκε στο event τους. Οι **εξαρτήσεις** όμως είναι
παράγωγες, άρα αλλαγή στο `requires` ισχύει αμέσως και για τις παλιές.

## Πρόγραμμα εργασίας, παρουσίες & συγκεντρωτικό

**Το πρόγραμμα είναι υποχρεωτικό στην πρόσληψη**, όπως η σύμβαση. Κάθε πρόσληψη
υποβάλλει **Ε3 και ΟΧΕ** στο ΕΡΓΑΝΗ. Πλήρης απασχόληση = **40 ώρες/εβδομάδα**
(5 × 8:00 ή 6 × 6:40) — ελέγχεται ότι οι ώρες του προγράμματος συμφωνούν με τη
σύμβαση.

Δύο τύποι, και οι δύο υποβάλλονται στο ΕΡΓΑΝΗ και αλλάζουν με νέα υποβολή:

1. **Σταθερό εβδομαδιαίο** (`WorkScheduleAssigned`)
2. **Ημερήσιο ανά ημέρα** (`DailyScheduleAssigned`) — **υπερισχύει** του
   εβδομαδιαίου για τις ημέρες που ορίζει (κενό ωράριο = ρεπό)

**Παρουσίες**: είτε καταγράφονται αναλυτικά ανά ημέρα (`AttendanceRecorded`),
είτε **τεκμαίρονται από το πρόγραμμα**.

**Μηνιαίο συγκεντρωτικό (ATTENDANCE_APPROVAL)** — προηγείται της μισθοδοσίας και
την ξεκλειδώνει. Το σύστημα προτείνει ημέρες εργασίας / αδειών / άνευ αποδοχών
και υπολογίζει τις **προβλεπόμενες ημέρες ΕΦΚΑ**· όλα διορθώνονται χειροκίνητα
στη σελίδα `/attendance` και μετά εγκρίνονται.

➜ **Η μισθοδοσία υπολογίζεται από τις ΗΜΕΡΕΣ ΕΦΚΑ** του εγκεκριμένου
συγκεντρωτικού: μισθωτός = `μισθός × ημέρες / 25`, ημερομίσθιος =
`ημερομίσθιο × ημέρες`. Χωρίς έγκριση, η μισθοδοσία απορρίπτεται.

## Μισθωτοί & Ημερομίσθιοι — οι 25 ημέρες

Οι **25 ημέρες ασφάλισης/μήνα** είναι **παραδοχή** της ελληνικής νομοθεσίας, όχι
μέτρηση: ο μισθωτός πλήρους απασχόλησης που δούλεψε **όλες** τις εργάσιμες (21,
22, ή 26 σε εξαήμερο) παίρνει 25 ημέρες. Η αδικαιολόγητη απουσία αφαιρείται από
το 25 **αναλογικά** προς τον μήνα (πενθήμερο ≈ 1,2 ημέρες ασφάλισης ανά ημέρα
απουσίας, εξαήμερο ≈ 1,0), και η αναλογία υπολογίζεται πάντα προς τις ημέρες
προγράμματος **ολόκληρου** του μήνα — ώστε πρόσληψη/αποχώρηση στη μέση του μήνα
να δίνει αναλογία, όχι πλήρες 25.

- **Μερική απασχόληση** (`weekly_hours < 40`): ασφαλίζονται οι πραγματικές
  ημέρες· ο κατώτατος ελέγχεται με αναλογία ωρών· στην ΑΠΔ «Πλήρες Ωράριο» = 0.
- **Ημερομίσθιοι**: μικτά = ημερομίσθιο × ημέρες. Δώρο Χριστουγέννων 25
  ημερομίσθια, Δώρο Πάσχα 15, Επίδομα Αδείας έως 13 (αναλογία 1/8).

## Κατώτατος μισθός

`config.MINIMUM_WAGE_HISTORY`, με ημερομηνίες ισχύος (ΚΥΑ 8934/2026: 920 €/μήνα
& 41,09 €/ημέρα από 1/4/2026· 880/39,30 από 1/4/2025· 830/37,07 από 1/4/2024).
Ελέγχεται **στην πρόσληψη** (με το όριο της ημερομηνίας πρόσληψης) και **σε κάθε
περίοδο μισθοδοσίας** (με το όριο της περιόδου) — άρα μια αύξηση του κατώτατου
μπλοκάρει αυτόματα τη μισθοδοσία όσων έμειναν κάτω από το νέο όριο, με ονόματα
και ποσά στο μήνυμα.

## Αρχεία ΑΠΔ (e-ΕΦΚΑ & ΤΕΚΑ)

Το `apd_files.py` παράγει αρχεία **CSL01** Κοινών Επιχειρήσεων:

- **e-ΕΦΚΑ**: Γενικό Έγγραφο 2120927/16-12-2025. Εγγραφές τύπου 1 (363), 2 (178),
  **3 (162)**, 4 (46), EOF (3).
- **ΤΕΚΑ**: Τεχνικές Προδιαγραφές 10/03/2026 — εγγραφή τύπου **3 (148 bytes)**,
  χωρίς τα 3 πεδία Γραμμάτιο/Φορείς.

Κανόνες: zero-padded αριθμητικά, ποσά χωρίς το `V` (2.340,30 € → `0000234030`),
ημερομηνίες `ΗΗΜΜΕΕΕΕ`, κεφαλαία χωρίς τόνους, CRLF, encoding **cp1253**. Το
`test_apd_files.py` ελέγχει τις θέσεις πεδίων **ανά byte**.

Για `teka_member=True`: στην ΑΠΔ e-ΕΦΚΑ οι εισφορές μειώνονται κατά την
επικουρική (Ειδική Περίπτωση «09», Φορέας «01-ΤΕΚΑ») και παράγεται δεύτερο CSL01
για το ΤΕΚΑ (3% + 3%).

**Τα Δώρα δεν έχουν δική τους υποβολή**: μπαίνουν στο αρχείο ΑΠΔ της **επόμενης**
περιόδου — Δώρο Χριστουγέννων → περίοδος 1/(Υ+1), Δώρο Πάσχα → 5/Υ, Επίδομα
Αδείας → ο μήνας μετά την άδεια.

uv run -m webapp        # http://localhost:8000

| Σελίδα | Περιεχόμενο |
|---|---|
| `/` | Επισκόπηση: στατιστικά, γραφήματα, επόμενες υποχρεώσεις |
| `/obligations` | **Χρονολόγιο** (φίλτρα: Εκκρεμείς / Ολοκληρωμένες / Όλες) + λεπτομέρειες + ενεργοποίηση |
| `/persons` | Μητρώο προσώπων· καρτέλα με όλες τις περιόδους + επαναπρόσληψη |
| `/employments` | Πρόσληψη με αναζήτηση· σύμβαση, ασφάλιση, πρόγραμμα, παρουσίες, άδειες, αποχώρηση |
| `/leaves` | Κεντρικό ετήσιο timeline αδειών με μετακίνηση και resize ανά ημέρα |
| `/attendance` | Μηνιαίο συγκεντρωτικό — επεξεργασία ημερών ΕΦΚΑ & έγκριση |
| `/payroll` | Μισθοδοσία περιόδου, Δώρα, Επίδομα Αδείας |
| `/submissions` | ΑΠΔ e-ΕΦΚΑ/ΤΕΚΑ, ΦΜΥ, καταβολές |

- **Χρωματικός κώδικας**: γκρι = ολοκληρωμένη, πράσινο = διαθέσιμη, πορτοκαλί =
  λήγει εντός 14 ημερών, κόκκινο = εκπρόθεσμη ή μπλοκαρισμένη (με την αιτία).
- **Λεπτομέρειες**: τι ΘΑ κάνει η υποχρέωση (preview ανά εργαζόμενο) ή τι ΕΚΑΝΕ
  (πραγματικά events, αρχεία, σύνολα), μαζί με «Προαπαιτεί» / «Ξεκλειδώνει».
- **Ημερομηνία αναφοράς** (⏱ header): αλλάζει το «σήμερα» **όλου** του UI —
  ταξίδι στον χρόνο για να δοκιμάζεται ολόκληρος ο κύκλος.
- Κενή βάση: κουμπί δημιουργίας δοκιμαστικών δεδομένων.

## Πριν από παραγωγική χρήση

1. **Συντελεστές**: οι τιμές ΕΦΚΑ/ΤΕΚΑ και η φορολογική κλίμακα στο `config.py`
   είναι **ενδεικτικές** — επιβεβαιώστε τις από ΕΦΚΑ/ΑΑΔΕ/ΤΕΚΑ.
2. **Δεν υλοποιούνται**: τριετίες/προϋπηρεσία, υπερωρίες & προσαυξήσεις,
   ασθένεια (τριήμερο εργοδότη/επιδότηση ΕΦΚΑ), αποζημίωση απόλυσης, ΚΠΚ ανά
   ειδικότητα, άθροιση προϋπηρεσίας μεταξύ περιόδων του ίδιου έτους.
3. **ΕΡΓΑΝΗ**: τα JSON σχήματα δεν έχουν επαληθευτεί με τα επίσημα XSD.
4. Δεν αποτελεί λογιστική/φορολογική συμβουλή — απαιτείται έλεγχος από λογιστή.

## Επόμενα βήματα

- **Παράταση προθεσμίας**: το πεδίο `extension` δηλώνεται ήδη στο μητρώο τύπων —
  χρειάζεται event `ObligationExtended` + εντολή που επιβάλλει το όριο.
- Daemon/cron που τρέχει καθημερινά `pending_obligations(as_of=today)` και
  ειδοποιεί για όσα λήγουν.
- REST API πάνω από το `PayrollService`· εκτυπώσεις (αποδείξεις αποδοχών).
- Snapshots στο event store όταν μεγαλώσει ο όγκος.

## Desktop εφαρμογή (Windows)

Όλα τα αρχεία της στον φάκελο `desktop/`.

```powershell
.\desktop\build-windows.ps1                 # dist\misevent + installer-output\misevent-Setup-<έκδοση>.exe
.\desktop\build-windows.ps1 -SkipInstaller  # μόνο ο φάκελος dist\misevent (portable)
```

Απαιτεί [Inno Setup 6](https://jrsoftware.org/isinfo.php) για τον installer. Το
`desktop/launcher.py` τρέχει το ίδιο web UI τοπικά (τυχαία θύρα) και ανοίγει τον browser·
εικονίδιο στο system tray (κάτω δεξιά): δεξί κλικ → Open / Exit, διπλό κλικ → Open
(καθαρό Win32 μέσω ctypes, χωρίς επιπλέον βιβλιοθήκη).
Ο installer εγκαθιστά ανά χρήστη, χωρίς δικαιώματα διαχειριστή (~15MB).

### Νέα έκδοση

1. Όλες οι αλλαγές committed (το script αρνείται με «βρώμικο» working tree)
   και οι έλεγχοι περνούν: `uv run ruff check . && uv run pytest`.
2. Από τη ρίζα του repo:

   ```powershell
   .\desktop\release.ps1          # patch: 1.5.0 -> 1.5.1  (διορθώσεις)
   .\desktop\release.ps1 minor    # minor: 1.5.0 -> 1.6.0  (νέα features)
   .\desktop\release.ps1 major    # major: 1.5.0 -> 2.0.0  (ασύμβατες αλλαγές)
   ```

   Κάνει bump στο `pyproject.toml` (`uv version --bump`), commit «bump vX.Y.Z»,
   tag `vX.Y.Z` και push του `main` μαζί με το tag.
3. Το push του tag ξεκινά το GitHub Actions (`.github/workflows/windows-release.yml`):
   ελέγχει ότι το tag ταιριάζει με το `pyproject.toml`, τρέχει το
   `build-windows.ps1` (με smoke test) και ανεβάζει το
   `misevent-Setup-X.Y.Z.exe` στο **GitHub Release** του tag (σελίδα *Releases*
   του repo). Παρακολούθηση στην καρτέλα *Actions*.
4. Αν αποτύχει το build, διόρθωσε, και ξανάτρεξέ το για το ίδιο tag από
   *Actions → Build Windows installer → Run workflow* (πεδίο `tag`, π.χ. `v1.5.1`) —
   ανεβάζει ξανά τον installer στο υπάρχον Release.

### Πού σώζονται τα αρχεία (εγκατάσταση Windows)

| Τι | Πού |
|---|---|
| Πρόγραμμα (exe + βιβλιοθήκες) | `%LOCALAPPDATA%\Programs\misevent` |
| Βάση δεδομένων (όλες οι εταιρείες, χρήστες, παράμετροι) | `%LOCALAPPDATA%\misevent\misevent.db` |
| Κλειδί υπογραφής session | `%LOCALAPPDATA%\misevent\secret.key` |
| Αυτόματο αντίγραφο πριν από restore μίας εταιρείας (Audit log) | `%LOCALAPPDATA%\misevent\backups\<εταιρεία>\before-restore-*.json` |
| Αυτόματο αντίγραφο πριν από restore όλου του συστήματος | `%LOCALAPPDATA%\misevent\backups\system\before-restore-*.db` |

`%LOCALAPPDATA%` = `C:\Users\<χρήστης>\AppData\Local` (γράψε το στη γραμμή
διευθύνσεων του Explorer). Τα δεδομένα είναι **έξω** από τον φάκελο του
προγράμματος, οπότε μένουν άθικτα σε αναβάθμιση. Η απεγκατάσταση **ρωτά** αν θα σβηστεί και το
`%LOCALAPPDATA%\misevent` (προεπιλογή «No» — κρατά τα δεδομένα· «Yes» = πλήρης
καθαρισμός)· σε silent απεγκατάσταση δεν σβήνεται τίποτα.

**Backup / restore:** μενού «Σύστημα → Backup» (μόνο διαχειριστές). Η «Λήψη
backup» κατεβάζει ολόκληρη τη βάση (όλες οι εταιρείες, χρήστες, παράμετροι) ως
ένα αρχείο `.db`· το «Restore» την αντικαθιστά από τέτοιο αρχείο, αφού κρατήσει
αυτόματο αντίγραφο της τρέχουσας (βλ. πίνακα). Αν το backup δεν φορτώνεται,
επανέρχεται η προηγούμενη κατάσταση. Έτσι γίνεται και η μεταφορά σε άλλο
υπολογιστή: σε **πρώτη εκκίνηση** (μόνο ο αρχικός admin με τον προσωρινό
κωδικό, καμία εταιρεία με δεδομένα) η σελίδα σύνδεσης προσφέρει απευθείας
«Επαναφορά από backup», χωρίς σύνδεση· μετά συνδέεσαι με τους χρήστες του backup. Backup μίας μόνο εταιρείας: «Ρυθμίσεις → Audit log».

Για μικρό μέγεθος το πακέτο δεν περιέχει tkinter ούτε Pillow (το fpdf2 το
φορτώνει προαιρετικά). Το build τελειώνει με `--smoke-test`, που ανοίγει το UI και
παράγει ένα PDF, ώστε να φανεί αμέσως αν λείπει κάποιο module.
